1. Introduction to TLA+

TLA+ (Temporal Logic of Actions) is a high-level language designed for specifying and reasoning about complex systems, particularly concurrent and distributed systems. Developed by Leslie Lamport, TLA+ is founded on simple mathematics, primarily set theory and temporal logic, to describe system behaviors precisely. Its utility lies in identifying fundamental design errors that are often difficult and costly to detect and rectify in later stages of development. TLA+ specifications define system behaviors as sequences of states, with actions describing permissible state transitions.

2. Core TLA+ Concepts and Syntax

A TLA+ specification is typically organized into modules. Understanding the basic structural elements, declaration of parameters, definition of operators, and the role of standard libraries is foundational to writing TLA+ specifications.

Module Structure

---- MODULE ModuleName ----
EXTENDS Naturals, Sequences (* Import standard modules *)

CONSTANTS C1, MaxRequests   (* Declare constant parameters *)
VARIABLES v1, queue         (* Declare state variables *)

(* Operator definitions, assumptions, etc. follow *)
====

General Operators and Expressions

  • Logical: /\ (and), \/ (or), ~ (not), => (implies), <=> (iff)
  • Quantifiers: \A x \in S: P(x) (forall), \E x \in S: P(x) (exists)
  • Equality: = (equals), /= or # (not equals)
  • Conditional: IF P THEN E1 ELSE E2
  • Let-In: LET defs IN expr for local definitions.

3. Sets

In TLA+, sets are unordered collections of unique elements, derived from ZF set theory. They are a fundamental data structure.

Operator Syntax Description Example
Element of e \in S Checks if `e` is in set `S`. 1 \in {1, 2}
Union S1 \union S2 Elements in `S1` or `S2`. {1} \union {2} is {1,2}
Intersection S1 \intersect S2 Elements in both `S1` and `S2`. {1,2} \intersect {2,3} is {2}
Difference S1 \ S2 Elements in `S1` but not `S2`. {1,2} \ {2} is {1}
Powerset SUBSET S The set of all subsets of `S`. SUBSET {1} is {{}, {1}}
Cardinality Cardinality(S) Number of elements in finite set `S`. Cardinality({1,2}) is 2
Filter {x \in S : P(x)} Set of `x` in `S` where `P(x)` is true. {x \in 1..4 : x%2=0} is {2,4}
Map {e(x) : x \in S} Set of `e(x)` for each `x` in `S`. {x*x : x \in {1,2}} is {1,4}
Choose CHOOSE x \in S : P(x) An arbitrary `x` in `S` where `P(x)` is true. CHOOSE x \in {3,5}:x>4 is 5

4. Sequences

Sequences represent ordered collections. Fundamentally, they are special functions with a domain of `1..n`, making them 1-indexed.

Operator Syntax Description Example
Construction <<e1, e2>> Creates an ordered sequence. <<1, "a", 1>>
Length Len(s) Returns the number of elements. Len(<<10,20>>) is 2
Head Head(s) Returns the first element. Head(<<"a","b">>) is "a"
Tail Tail(s) Returns the sequence without its first element. Tail(<<1,2,3>>) is <<2,3>>
Append Append(s, e) Adds an element to the end of a sequence. Append(<<1>>, 2) is <<1,2>>
Concatenation s1 \o s2 Concatenates two sequences. <<1>> \o <<2,3>> is <<1,2,3>>
Access s[i] Accesses the i-th element (1-indexed). <<"x","y">>[2] is "y"

5. Sets vs. Sequences

Choosing the right data structure is key. Sets are for unordered, unique items, while sequences are for ordered lists where duplicates matter.

Feature Sets Sequences
Ordering Unordered Ordered
Duplicates Not allowed (unique) Allowed
Indexing No direct indexing 1-based integer indexing s[i]
Construction {e1, e2} <<e1, e2>>
Typical Use Resource pools, state spaces Queues, logs, buffers

6. Functions

Functions are first-class mappings from a domain set to values. Records and sequences are special cases of functions.

Construct Syntax Description
Definition [x \in S |-> expr] Defines a function over domain `S`.
Application f[arg] Applies function `f` to `arg`.
Domain DOMAIN f Returns the domain set of function `f`.
Update [f EXCEPT ![key] = val] Creates a new function, with `key` mapping to `val`.
Set of Functions [S -> T] The set of all functions from domain `S` to co-domain `T`.

7. Records

Records group data under named fields. They are functions where the domain is a set of strings.

Construct Syntax Description
Definition [f1 |-> v1, f2 |-> v2] Creates a record with named fields.
Field Access record.fieldName Accesses the value of a field.
Update [r EXCEPT !.f1 = newV] Creates a new record with an updated field.
Set of Records [f1: S1, f2: S2] The set of all records with a given structure.

8. Temporal Logic Operators

Temporal logic specifies properties across sequences of states (behaviors), such as safety (bad things never happen) and liveness (good things eventually happen).

Operator Syntax Meaning Type
Prime var' Value of `var` in the next state. Action
Unchanged UNCHANGED var `var` has the same value in the next state. Action
Enabled ENABLED A True if action `A` can occur from the current state. Predicate
Always (Box) []F or [][F]_vars Formula `F` is true for all subsequent states. Temporal
Eventually (Diamond) <>F Formula `F` is true for some subsequent state. Temporal
Weak Fairness WF_vars(A) If `A` is persistently enabled, it must eventually occur. Temporal
Strong Fairness SF_vars(A) If `A` is infinitely often enabled, it must eventually occur. Temporal
Leads To F ~> G If `F` becomes true, `G` will eventually become true. Temporal
